# 02 - 2 天 Demo 范围界定与关键技术取舍

---

## 1. 硬性约束与关键避坑

本次 2 天（48 小时）AI Coding Demo 的核心约束如下：
- **开发周期**：仅 2 天，全链路高度依赖 AI Coding 提效与自动化闭环测试。
- **硬性验收标准**：
  1. **网站真实可用**：运行稳定、交互真实、无演示白屏；
  2. **公网别人能看**：手机（4G/5G）、微信、他人电脑可直接打开独立网页（无编辑器外壳）；
  3. **真实数据持久化**：不同设备写入数据刷新不丢、跨端可见，改版重发布不丢旧数据。

### 必须避开的两个致命坑
1. **不能用 Sandpack 当“正式发布页”**：Sandpack 依赖境外打包服务，国内网络加载慢/易失败且带沙盒壳子，无法满足“公网秒开给别人看”。
2. **如果部署到 Vercel，不能用本地 SQLite**：Serverless 文件系统重启即清空，无法满足真实数据持久化，必须接入云端数据库（或部署在带持久化磁盘的云主机）。

## 2. 哪些选择已被抽象层吸收（无需过早拍板）

得益于六边形架构（Ports & Adapters），以下两类决策不会在早期锁定系统，**可先写接口与 Mock/MVP 实现，上线前或演进时通过环境变量动态切换**：

### 2.1 数据库介质与最终部署位置（云主机 Postgres vs Vercel + Neon/Supabase）
只要遵守 3 条工程约束，同一套代码可无缝迁移：
1. `ProjectRepository` 与 `AppCloudRuntime` 仅依赖标准 PostgreSQL 协议（本地测试用内存实现 `InMemory`，正式环境读 `DATABASE_URL`）；
2. 编译环节（`esbuild`）全在内存中完成输入输出，不依赖宿主机临时磁盘文件；
3. AI 生成与自动修错长任务走 **SSE 流式响应**，避免触发 Serverless 同步超时。

**后期部署取舍参考**：
- **独立云主机（Node 常驻 + Postgres）**：*得到* 国内直连稳定、无 Serverless 时长限制、可随时跑无头浏览器检查；*失去* 需手动配置一次服务器与 HTTPS。
- **Vercel + 云 Postgres（Neon/Supabase）**：*得到* Git Push 零运维上线；*失去* 国内访问 `.vercel.app` 受阻（需绑自定义域名）及免费版函数执行时长限制。

### 2.2 `AppCloud` 能力插件粒度（`db` / `auth` / `billing` / `ai`）
通过将 `AppCloudRuntime` 拆分为按需声明的能力插件（`capabilities`），在 `ProductPlan` 中声明当前应用所需的集合，避免简单应用被登录/支付代码污染：
- **仅 `db`**：一次生成成功率最高、代码量最少；但应用无账号隔离，属于公开共享数据。
- **加上 `auth`**：生成网站具备真实注册登录与按用户隔离数据能力；代价是后端多 ~2 小时开发且 AI 编写鉴权跳转时轻微增加报错风险（由 Auto-Fix 兜底）。
- **加上 `billing`**：2 天内用模拟收银台改 `user.plan = 'pro'`，即可低成本讲通 Atoms 的“Vibe Business 付费解锁”故事，后续接口不变可平滑切换真 Stripe。

## 3. 唯一核心架构分水岭：路线 A vs 路线 B（已选定 **路线 A+**）

| 对比维度 | 路线 A：纯前端 SPA + 平台托管通用 `atomsCloud` BaaS | 路线 B：AI 生成独立全栈代码 + 独立 DB 迁移 + 独立容器运行 |
| :--- | :--- | :--- |
| **AI 编码范围** | 专注前端 React + Tailwind + 调用固定 `@atoms/cloud` SDK | 同时生成前后端 API、ORM/SQL 迁移、环境变量 |
| **得到什么** | 1. **2 天极高交付确定性**：消灭 80% 服务端启动/端口/SQL 迁移失败；<br>2. **100ms 编译闭环**：单测与 Auto-Fix 极快；<br>3. **公网秒开 + 零容器运维**：发布页即原生静态 HTML，小服务器即可托管数百站点；<br>4. **改版不丢数据**：JSONB 通用表天然兼容前端迭代。 | 1. **能力上限极高**：可写任意自定义服务端算法、定时任务、复杂多表 SQL 强事务；<br>2. **源码零耦合**：导出的 ZIP 可脱离平台独立启动。 |
| **失去什么** | 1. 不支持运行独立后台常驻服务（如 Python 算法、定时爬虫）；<br>2. 导出源码需保留或替换 `@atoms/cloud` SDK 对接。 | 1. 容器编排、反向代理、休眠唤醒与动态迁移会吞噬大半工期；<br>2. AI 报错面成倍放大，容器重启慢，2 天极易失控翻车。 |

### 最终选定：**路线 A+（路线 A 为底座 + `ai/proxy` 扩展口 + 接口面向未来兼容路线 B）**
- 在 2 天内依托 `esbuild` + 通用 `@atoms/cloud` 保证 100% 稳定交付；
- 在 `AppCloudRuntime` 预留 `ai`（及通用代理）能力位，满足生成页面内安全调用大模型等轻量服务端诉求，避免暴露平台密钥；
- `AppBuilder` 保持 `VirtualFS → BuildArtifact` 抽象，未来如需扩展重后端容器型应用，只需并行新增 `ContainerBuilder` 适配器，无需推翻现有架构。

## 4. 2 天 MVP 功能边界（已最终拍板）

### P0 + 已纳入的核心亮点（本次必须闭环交付）
1. **精简 3 角色 SOP 协作流**：`Iris 调研卡片 → Emma 产品与数据表方案（暂停等待人工确认）→ Alex 编码`；
2. **模型切换下拉框（`listModels`）**：工作台直观展示当前可用模型（离线 Mock / 已配置 Key 的 OpenAI、Anthropic、DeepSeek 等）并支持切换；
3. **服务端 `esbuild` 编译 + 编译/运行双闭环 Auto-Fix（≤ 2 轮）**：保障生成即可用、不白屏；
4. **真 SEO / OG 分享卡片元信息**：构建 HTML 时自动注入 `<title>`、`<meta name="description">` 及 Open Graph 标签，保证群聊分享与浏览器标签质感；
5. **云端通用 BaaS 底座（`db` + `auth` + `billing` + 预置 `@atoms/cloud` SDK）**：
   - 本地默认采用 **`PGlite`**（`.data/pglite`）实现真 Postgres SQL 持久化落盘，线上填 `DATABASE_URL` 一秒切换标准 `pg`；
   - 收款链路采用 **Mock + Creem Test Mode 异步结账与签名 Webhook 验签**，免审核跑通真实订阅解锁闭环，后续换 Live Key 即可真实收款；
6. **工作台 `Cloud 数据` 面板**：右侧工作台提供 `实时预览 | 源码 | Cloud 数据` 三大 Tab，实时查看与管理已入库的集合记录和注册用户，让“真持久化”肉眼可见；
7. **独立公网路由 `/s/[slug]` + 一键发布 + 草稿/线上版本隔离 + 二维码分享**；
8. **多轮对话迭代改版 + ZIP 源码导出**；
9. **极简版双路 Race Mode**：基于已定义的 `branchId` 与 `RaceBranch`，在方案确认时支持选择【并发 2 套风格二选一】，选定后合入草稿继续迭代发布。

### 明确砍掉（2 天内坚决不做）
- ❌ Docker / E2B 动态多容器编排；
- ❌ AI 动态生成 SQL / Prisma Migration；
- ❌ 预览区点选元素局部拖拽/修改（Visual Editor 精细点选先不做）；
- ❌ 图片/文件对象存储上传（`storage`）；
- ❌ 独立 SEO Agent（Sarah）、Google Ads Agent（Adrian）、BI 数据分析 Agent（David）；
- ❌ 平台自身复杂计费系统、工作台账号登录、团队 RBAC 与 GitHub OAuth 双向同步（先用 ZIP 导出代替）。

## 5. Day 2 结束时的 4 步硬性验收流程

1. **SOP 生成**：输入需求（例如“做一个活动报名与签到管理系统，带管理员列表与状态统计”），跑完 `Iris → Emma（人工确认）→ Alex` 流程并预览正常；
2. **跨网秒开**：点击【一键发布】，使用**另一部手机（关闭 Wi-Fi 走 4G/5G）**打开 `/s/[slug]`，1 秒内正常渲染，无白屏、无沙盒边框；
3. **真实持久化**：在手机端注册/提交一条新报名数据 → 手机刷新不丢 → 电脑端刷新同一个 `/s/[slug]` 链接立刻看到该记录；
4. **无损迭代**：回到工作台输入“主色调改成深蓝色、增加导出 CSV 按钮” → 点击【重新发布】 → 公网页面更新成功，且第 3 步提交的历史数据 100% 保留。
