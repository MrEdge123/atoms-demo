# Atoms 实测使用体验报告与视觉排版改造规范

> 本文档基于对已登录 `https://atoms.dev`（`/zh/homepage` → `/zh/dashboard` → `/zh/chat/<id>`）的实时浏览器实操采样，结合 `atoms-demo` 当前前端实现梳理而成，作为后续 UI / UX 对齐改造的统一基准蓝本。

## 一、实测背景与端到端使用体验报告

### 1.1 实测路径与安全边界
- **测试视口与会话**：桌面端 `1123 × 909`，在已登录账户会话下只读检查营销主页、启动大厅及工作台全部公开视图与浮层。
- **实测轻量化输入**：在启动台输入并提交真实需求——`做一个极简科技沙龙活动报名页，包含活动日程、报名表单和已报名列表`，完整体验从需求触发、流式构建、多 Tab 切换（`预览 / 概览 / 代码 / 素材 / 更多 / Atoms 云 / 营销 / 计划器`）到 `分享`、`发布` 浮层的全流程。
- **操作边界**：未修改或删除用户已有项目；未点击任何实际付款、升级订阅或账户安全设置动作。

### 1.2 端到端流程与体感复盘

1. **入口分流（`/zh/homepage` → `/zh/dashboard`）**
   - `/zh/homepage` 在登录后依然保持公开官网落地面貌，仅在右上角将主 CTA 切换为 `进入 Atoms`（跳转 `/zh/dashboard`），并在定价卡片标注当前所处计划。
   - 真正的工作台入口是 `/zh/dashboard` **启动大厅**：左侧带 `270px` 常驻导航栏，顶部居中展示计划徽标，首次进入弹出可关闭的 `从现成的模板开始` 引导浮层（3 列 18 套模板卡片 + 底部黑色胶囊 `探索全部模板 ->`）。

2. **启动台交互与能力组织（`/zh/dashboard`）**
   - 问候语上方放置可点击的 Atoms 几何标志 / 团队成员头像簇，点击可切换展示团队成员（如 `认识你的 AI 团队` / Mike）。
   - 主提示词输入台底部收纳全部复杂控制项，界面极度干净：
     - 左下角 `+`（更多功能触发器，带小红点提示）展开 9 项高级能力开关：`团队模式`、`使用模板创建`、`定时任务`、`附件`、`连接器`、`视频 Seedance 2.5`、`深度研究`、`竞赛模式`（Free 档置灰禁用）、`主题`。
     - 右下角 `构建 ▾` 下拉弹出模式选择：`构建`（通用构建模式，默认）vs `计划 [新增]`（Mike 规划并分配构建任务）。
   - 输入台下方为快捷场景胶囊（`幻灯片`、`游戏`、`视频`）与可切换的 `发现 / 项目 / 模板` 三栏卡片流。

3. **提交与流式构建过程（`/zh/chat/651ad5a30319440a97eb494d4c43b4a8`）**
   - 点击发送后发送按钮短暂旋转，页面秒级路由至 `/zh/chat/<id>?block=Browser-RT`，同时 `270px` 左侧栏自动收起，进入两栏沉浸式工作台。
   - 由于本次选择了默认 `构建` 模式（未切入 `计划` 或 `团队模式`），由 `Alex · 工程师` 单角色直接推进，共 `已处理14步`：
     - 依次执行读取脚手架、终端命令行（含双会话 `会话 1 / 会话 2`）、后台生图 `homepage_reference.png`、写入设计规范 `DESIGN.md` 与源码（`index.css`、`event.ts`、`useRegistrations.ts`、`Index.tsx`）、Lint/Build 及 `可视化检查`。
     - 全程约 `90–110 秒` 完成构建，积分从 `15.00` 消耗至 `9.93`（累计消耗 `5.07` 积分）。

4. **智能体视角跟随机制（Agent-Following）**
   - 构建过程中右栏处于「正在跟随智能体」自动联动状态，会随 Alex 当前工具调用自动切换 URL query 与 Tab：`Browser-RT`（初始化）→ `Terminal`（命令流与生图进度）→ `Editor`（文件树中正在编辑的目录/文件实时转圈）→ `Browser-RT`（最终页面预览）。
   - 一旦用户在右栏主动点击其他 Tab，自动跟随解除，顶部出现蓝色描边 `关注` 按钮，方便随时回到智能体焦点。

5. **构建完成后的闭环体验**
   - 首个可用预览产出于右侧后，顶部立刻解锁 `概览` Tab，激活右上角 `分享 / 升级 / 发布` 按钮与移动端宽度预览按钮（`显示移动预览`），同时预览画布底部居中浮出 **`设计工具`** 悬浮胶囊（`选择元素`、`修改文本`、`主题`）。
   - 生成的成品默认呈现高完成度的现代编辑风视觉（例如本次产出的 `SIGNAL / 科技沙龙` 页面，包含暖纸白留白、大字标题排版、活动日程、报名名额进度条及报名列表）。

### 1.3 核心 UX 亮点与实测摩擦

| 维度 | 实测亮点（值得直接借鉴） | 实测摩擦（`atoms-demo` 改版可避坑） |
| --- | --- | --- |
| **色彩心理** | 登录后工作台切为暖米白纸感（`#fcfcfb / #f8f8f6 / #f3f3f0`），极轻网格边框 + 单一皇家蓝 `#4267ff` + 黑色高对比药丸，长时间使用无疲劳感 | — |

| **规划与门禁** | 左栏顶部悬浮 `持续构建 2/4` 引导进度卡与清晰的版本卡，新手路径明确 | 默认 `构建` 模式会跳过方案确认直出代码；`atoms-demo` 已具备完整的 Iris→Emma 确认门禁，可保留该硬门禁并用 Atoms 的结构化卡片提升交互质感 |

## 二、Atoms 官方设计系统与 CSS Token 规范（真实提取）

> 注意区分两套官方皮肤：官网营销落地页采用 `html.light[data-ui-skin="atoms"]`（冷中性灰 `#f6f6f6` / `#ebebea` + 深炭 `#232324` Footer）；**已登录工作台实际采用 `html.light[data-ui-skin="claude"]`（暖米白纸感体系）**。`atoms-demo` 工作台改版建议主用 **`claude` 暖米白工作台体系**，局部卡片/光晕参考官网气质。

### 2.4 字体、圆角与阴影微质感 Token

- **字体栈**：
  - 主界面无衬线：`IBM Plex Sans, ui-sans-serif, system-ui, sans-serif`（正文常规 `14px/22px`、Composer 输入 `16px/24px`、大标题 `clamp(32px, 3.17vw + 19.6px, 44px)` 字重 `500–600`）。
  - 编辑风点缀衬线：`IBM Plex Serif, serif`（仅用于启动页或关键数据指标点缀）。
  - 代码与路径：`IBM Plex Mono, ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace`。
- **圆角尺度**：
  - `8px`：下拉菜单项、文件树行、紧凑工具按钮

  - `24px`：启动台居中提示词输入台
  - `999px`：所有主/次行动胶囊（`rounded-full`）、模式胶囊、`设计工具` 悬浮胶囊、追问建议芯片
- **分段开关（Segmented Control）**：
  - 轨道底色 `rgba(12, 12, 12, 0.04)`，内边距 `2–3px`，圆角 `8px–999px`；选中项背景 `#ffffff`、细框 `rgba(12, 12, 12, 0.12)`、微阴影 `0 1px 2px rgba(12, 12, 12, 0.04)`。

### 3.3 各核心子模块排版细则

1. **统一超薄顶栏（`44px` 高）**
   - 取消厚重底框线，左栏与右栏共用一个 `44px` 高顶条：
     - 左区：侧栏展开按钮、项目标题下拉（点击弹出回首页、设置、克隆、重命名、收藏、外观主题、帮助等菜单）、`28×28px` 任务进度清单开关、历史版本图标、折叠聊天栏按钮。
     - 右区：高 `30px` 的分段工具轨道（`预览 | 概览 | </> 代码 | 素材 | ··· 更多`）；在 `预览` Tab 下紧接设备切换（`24×24px` 移动视图切换）、刷新/回首页、路由药丸（`首页 ▾`, `152×24px`）、新标签打开；最右侧为 `分享`、`升级`、`发布`（`#4267ff` 蓝）。
     - **实测改造提醒**：建议在宽屏（`>=1280px`）保留文字标签（如 `分享`、`发布`），避免直接缩成 `30×30px` 盲猜图标。

2. **左栏协作流（实测 `496px`，建议桌面端区间 `390px–460px`）**
   - **顶部引导进度条**：`476×52px` 白底圆角浮条，点击就地展开 `4` 步引导卡（已达成项为实心黑圆勾，未达成项右置 `预览` / `发布` 黑色微胶囊），清楚指引用户从「输入想法 → 完成构建 → 看预览 → 发布上线」。
   - **消息与工具折叠**：
     - 用户消息：右对齐暖灰气泡（`#f3f3f0`），上方附轻量日期时间。

## 四、`atoms-demo` 现有界面差距诊断与逐项改造映射表

### 4.1 现状问题诊断

对照现有代码文件，目前界面丑/笨重的根源集中在 4 处：
1. **全局视觉压抑偏旧**：[globals.css](../src/app/globals.css) 与 [layout.tsx](../src/app/layout.tsx) 硬编码 `bg-slate-950` + `indigo-600` + `rounded-lg`，呈现早期后台管理模版观感，缺少留白与呼吸感。
2. **缺少启动入口，状态混杂拥挤**：打开 [Workbench.tsx](../src/components/Workbench.tsx) 直接露出黑色空分栏，左侧同时存在顶部「输入产品想法」框与底部「迭代」框两套表单，顶部依赖原生丑陋 `<select>` 切换项目和模型。
3. **协作过程直接吐原始调试日志**：左栏 `events.map(...)` 把 `role_start`、`thought`、`file_write`、甚至 `JSON.stringify(ev.payload)` 逐条平铺，技术调试噪音极强；[CloudDataPanel.tsx](../src/components/CloudDataPanel.tsx) 也同样沿用黑底细边框表格。
4. **独立辅助页风格割裂**：[checkout/mock/page.tsx](../src/app/checkout/mock/page.tsx) 走深蓝+琥珀黄风格，而未发布提示页在 [s/[slug]/route.ts](../src/app/s/[slug]/route.ts) 使用默认浅灰简陋卡片，整体未形成统一产品识别度。

## 五、建议的改版实施分期（后续行动路线）

为保证改动可控且每次都能跑通完整回归验证，建议按以下 3 个阶段推进：

- **Phase A（P0：视觉地基与双态框架）**
  - 在 [globals.css](../src/app/globals.css) 和 [layout.tsx](../src/app/layout.tsx) 接入暖米白 Token、字阶（`IBM Plex Sans / Mono`）与通用阴影/圆角变量。
  - 将 [Workbench.tsx](../src/components/Workbench.tsx) 重构为「**启动大厅（新建/空项目）↔ 沉浸双栏工作台（进入项目后）**」两态切换，落实 `44px` 极简顶栏、`30px` 分段胶囊与定制模型切换浮层，去掉所有原生 `<select>`。

- **Phase B（P1：AI 协作流升级与右侧全视图浅色化）**
  - 重做左栏消息渲染器：落地 Iris / Emma / Alex 角色徽章与虚线时间轴、可折叠文件写与 Auto-Fix 摘要卡、`持续构建 4 步进度条`、增强版 Emma 方案确认卡、蓝框最新草稿版本卡，以及底部统一 Composer（支持切换「迭代修改 / 重规划新想法」）和待确认/Race 锁保护。
  - 重做右栏与 [CloudDataPanel.tsx](../src/components/CloudDataPanel.tsx)：浅色预览画框与 Race 双风格对比框、浅色高对比源码阅读器、白底 Bento 化 Cloud 数据表与 `分享/发布二维码` Popover。

- **Phase C（P2：端到端质感统一与可选进阶）**
  - 统一 [checkout/mock/page.tsx](../src/app/checkout/mock/page.tsx) 与 [s/[slug]/route.ts](../src/app/s/[slug]/route.ts) 404 页视觉。
  - （可选）增加顶栏/侧栏「暖米白（默认）/ 深炭黑（`#171717`）」主题一键切换开关。
  - （可选）同步打磨 `MockLLMProvider` 默认生成模板的现代编辑风排版与配色，使“预览框里的生成站点”同样具备高水准设计感。
